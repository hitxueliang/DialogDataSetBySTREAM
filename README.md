# DialogDataSetBySTREAM

DialogDataSetBySTREAM is a high-quality multi-turn dialogue dataset generated by STREAM. It covers three main domains: car sales, hotel reservations, and restaurant bookings. The dataset is designed to provide rich linguistic data for tasks such as dialogue systems, Large Language Model (LLM) fine-tuning, and intent recognition.

## Dataset Overview

This dataset simulates interactions between users and assistants in real-world scenarios. Each domain consists of four core components:

1.  **`dialogue_{idx}.json`**: Contains the actual multi-turn dialogue content. Each domain's dialogue data is split into multiple files (e.g., `dialogue_0.json`, `dialogue_1.json`, etc.). Each dialogue has a unique ID and is associated with a user profile, assistant profile, and dialogue plan.
2.  **`user_profile.json`**: User profile data, including age group, inferred occupation, purchasing/booking mindset, core needs, and primary concerns.
3.  **`assistant_profile.json`**: Assistant profile data, defining the assistant's role, professional qualifications, communication style, business scope, and domain-specific expertise.
4.  **`dialogue_plan.json`**: Dialogue plans that specify the overall rhythm of the conversation (e.g., ice-breaking, need discovery, recommendation, closing) and key milestones.

### ID Naming Rules and Data Sources

The IDs in `user_profile.json`, `assistant_profile.json`, and `dialogue_plan.json` follow specific naming rules to distinguish data sources:

- **`stream`**: IDs containing "stream" indicate that the data originates from **streaming data** (e.g., extracted from real-time interactions in live streaming rooms or videos).
- **`seed`**: IDs containing "seed" indicate that the data originates from **seed dialogues** (from the public dataset [RiSAWOZ](https://github.com/terryqj0107/RiSAWOZ)).

## Usage Instructions

The dataset is stored in JSON format and can be read and processed using the standard Python `json` library. Each dialogue is linked to its corresponding profiles and plan via corresponding IDs, facilitating in-depth scenario simulation and analysis.
